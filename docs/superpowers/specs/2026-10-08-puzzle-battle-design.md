# Puzzle Battle 設計書

日付: 2026-10-08

## 1. 目的と前提

- **目的**: 友達同士で遊ぶためのブラウザゲームサイト。テトリス・ぷよぷよ・スイカゲームの3つが遊べる。
- **成功の条件**: 3ゲームがちゃんと遊べること。リンクを送るだけで、ログインもインストールもなしにオンライン対戦がつながること。
- **対応端末**: PCを優先して作る（キーボード操作）。そのあとスマホのタッチ操作を足す。
- **対戦人数**: 1対1のみ。
- **割り切ること**: チート対策はしない。最初は凝った見た目にしない。最初からバランスを完璧にしようとしない（数値は1ファイルにまとめて、あとで調整する）。

## 2. 技術スタック

| 用途 | 使うもの |
|---|---|
| 言語・ビルド | TypeScript + Vite |
| 描画 | Canvas 2D |
| スイカの物理演算 | Matter.js |
| オンライン | Firebase Realtime Database + 匿名認証 |
| テスト | Vitest |
| 公開 | GitHub Pages（GitHub Actions でデプロイ）。Vite の `base` は `/puzzle-battle/` |
| ルーティング | ハッシュ方式（`#/home`、`#/room/ABC123`）。GitHub Pages が静的サイトのため |

## 3. 画面とモード

```
タイトル
 └ ホーム
    ├ ひとりで遊ぶ ─ ゲーム選択 → プレイ（エンドレス、ハイスコアは localStorage に保存）
    ├ チュートリアル ─ ゲーム選択 → 段階式レッスン
    ├ NPC対戦 ─ 自分のゲーム → NPCのゲーム → 難易度 → 対戦（2本先取）
    ├ オンライン対戦 ─ 部屋を作る / リンクで参加 → ロビー → 対戦（2本先取）
    └ 設定 ─ キー操作の表示、音量、タッチ操作 ON/OFF/自動
```

- 「同じゲーム対戦」と「異種対戦」は別モードにしない。ロビーで2人が選んだゲームの組み合わせで決まる。
- NPC対戦とオンライン対戦は同じ対戦の仕組み（`Match`）を使う。違うのは相手（`Opponent`）の実装だけ。
- 対戦画面: 左に自分の盤面（大）、右に相手の盤面（小、スナップショットから描画）。間に受け取り予定APのゲージと勝敗数を置く。

## 4. ゲームのルール

### 4.1 テトリス
- 盤面は10×20。上に見えない2行がある。ミノは7種1セットで配る（7-bag）。回転は SRS（壁蹴りを含む標準の回転ルール）。
- ホールドあり。NEXT は5個表示。ゴースト（落下位置の影）あり。
- DAS（押しっぱなしで動き始めるまでの時間）は133ms、ARR（その後の連続移動の間隔）は33ms。固定猶予は500msで、動かすたびにリセットする（最大15回）。
- ひとりモード: 10ライン消すごとに落下速度が上がる。
- 負け: 新しいミノが出現位置に置けないとき。

### 4.2 ぷよぷよ
- 盤面は6×12。上に見えない1行がある。色は4色。2個1組（組ぷよ）で落ちてくる。
- 回転は右回転・左回転。壁際では押し戻す。両側がふさがっているときは上下を入れ替える（クイックターン）。
- 4個以上つながると消える。連鎖あり。
- 得点 = 10 × 消した数 × max(1, 連鎖ボーナス + 連結ボーナス + 色数ボーナス)
  - 連鎖ボーナス: [0, 8, 16, 32, 64, 96, 128, 160, 192, 224, 256, 288, 320, 352, 384, 416, 448, 480, 512]
  - 色数ボーナス: [0, 0, 3, 6, 12]（同時に消えた色の数で引く）
  - 連結ボーナス: 4個→0、5→2、6→3、7→4、8→5、9→6、10→7、11個以上→10
- 負け: 左から3列目・上から12段目（出現位置）がふさがったとき。

### 4.3 スイカゲーム
- 容器の大きさは論理座標で幅400×高さ600。上から80の位置に「デッドライン」がある。
- フルーツは11種類。番号: 0さくらんぼ 1いちご 2ぶどう 3デコポン 4かき 5りんご 6なし 7もも 8パイナップル 9メロン 10スイカ
  - 半径: [12, 16, 22, 26, 33, 40, 47, 55, 63, 73, 85]
  - 落ちてくるのは0〜4番からランダム（シード付き乱数）。NEXT を1個表示する。
- 同じ種類が触れると1つ上の種類に合体する。スイカ同士は消える。
- 合体の得点: 新しくできたフルーツの番号を k として、(k+1)(k+2)/2
- 落とせる間隔は0.5秒に1回。
- 負け: 静止したフルーツの上端がデッドラインを越えた状態が2秒続いたとき。落としてから1秒以内のフルーツは判定しない。

## 5. 攻撃の仕組み（AP）

設定値はすべて `src/core/balance.ts` に置く。

### 5.1 AP を出す
| ゲーム | ルール |
|---|---|
| テトリス | 1列0、2列1、3列2、4列4。Tスピン: 1列2、2列4、3列6（Tスピンミニは0）。B2B（テトリスやTスピンを続けて出すこと）で+1。REN ボーナス表 [0,0,1,1,2,2,3,3,4,4,4,5]（それ以降は5）。全消しで+10 |
| ぷよ | おじゃま数 = floor((得点 + 前回の端数) / 70)。端数は次に持ち越す。AP = おじゃま数 / 6（6で割った余りも持ち越す）。連鎖が終わったときにまとめて送る |
| スイカ | 合体でできたフルーツの番号ごとの AP: 0〜3→0、4→1、5→1、6→2、7→2、8→3、9→4、10→5。前の合体から2秒以内の合体は連鎖として数える。連鎖3回ごとに+1。1回落としてから次に落とすまでの間に出た AP をまとめて送る |

### 5.2 AP を受け取る
| ゲーム | 1AP あたり | 1回で受け取る上限 | 仕組み |
|---|---|---|---|
| テトリス | おじゃま1列 | 8列 | 下からせり上がる。1回に受け取る分は穴を同じ列にあける |
| ぷよ | おじゃま6個 | 30個（5段） | 上から降る。隣のぷよが消えると一緒に消える |
| スイカ | おじゃま石1個（半径18） | 8個 | 上からランダムな位置に落ちる。石どうしは合体しない。フルーツが合体した中心から（新しいフルーツの半径 + 石の半径 + 10）以内にある石は砕ける |

上限を超えた分は、次の機会まで受け取り予定に残る。

### 5.3 共通ルール
- **相殺**: 自分が AP を出したら、まず受け取り予定の AP を減らす。余った分だけ相手に送る。
- **降ってくるタイミング**: テトリスはミノを固定してライン消しがなかったとき。ぷよは連鎖が全部終わったあと。スイカは次のフルーツを落としたあと。
- **予告**: 受け取り予定の AP は盤面の横にゲージで表示する。

## 6. 共通インターフェース

```ts
interface GameEngine {
  readonly kind: 'tetris' | 'puyo' | 'suika';
  update(dtMs: number, input: InputState): void;  // 1コマ進める
  receiveAttack(ap: number): void;                 // 受け取り予定に足す（相殺は中で処理）
  onAttack(cb: (ap: number) => void): void;        // 相殺後に余った AP を外に知らせる
  snapshot(): GameSnapshot;                        // 相手画面に送る、小さくまとめた盤面
  readonly pendingAttack: number;                  // 受け取り予定の AP
  readonly isOver: boolean;
  readonly score: number;
}

interface Opponent {
  start(seed: number): void;
  sendAttack(ap: number): void;           // 自分 → 相手
  onAttack(cb: (ap: number) => void): void; // 相手 → 自分
  onSnapshot(cb: (s: GameSnapshot) => void): void;
  reportSnapshot(s: GameSnapshot): void;
  reportLose(): void;
  onLose(cb: () => void): void;
  dispose(): void;
}
```

- ルール部分（`rules`）は描画や DOM に依存させない。Node 上で Vitest から動かせるようにする。
- 乱数はすべてシード付き（mulberry32）。同じシードなら、2人に同じ順番でミノ・ぷよ・フルーツが配られる。
- `NpcOpponent` は自分のブラウザの中で相手の `GameEngine` を AI に操作させる。`OnlineOpponent` は Firebase 経由で相手とやりとりする。

## 7. NPC（AI）

AI は入力（`InputState`）を作るだけ。ルールは人と同じエンジンを使う。

| 難易度 | テトリス | ぷよ | スイカ | 1手の時間 |
|---|---|---|---|---|
| かんたん | 評価の上位半分からランダムに選ぶ、ホールドなし | 置ける場所からランダム | x 座標ランダム | 1.2秒 |
| ふつう | 評価関数で一番いい場所 | 今の組ぷよだけ探索（連鎖数と形を評価） | 同じフルーツの真上を狙う | 0.6秒 |
| むずかしい | ホールドも使い、NEXT まで先読み | 今と NEXT の2組を探索 | 候補位置を評価（隣が同じフルーツか、高さ） | 0.35秒 |
| 鬼 | むずかしいと同じ考え方 | 3組を探索 | むずかしいと同じ考え方 | 0.15秒 |

- テトリスの評価関数: 盤面の高さの合計、穴の数、凸凹、消せるライン数に重みをかけて足す（Dellacherie 系）。
- 動きは「目標位置まで1マスずつ動かして回転する」入力の列を作り、その時間をかけて実行する。人っぽく見せるため。

## 8. チュートリアル

ゲームごとに3〜4ステップ。各ステップに説明文と達成条件がある。条件を満たすと次へ進む。

- テトリス: ①左右移動と回転 ②ハードドロップでライン消し ③ホールドを使う ④4列消しで攻撃
- ぷよ: ①移動と回転 ②4個つなげて消す ③2連鎖を組む
- スイカ: ①狙って落とす ②合体させる ③おじゃま石を砕く

決まった盤面から始まるようにする（ルールエンジンに初期盤面を渡せるようにする）。

## 9. オンライン対戦

### 9.1 部屋
- 部屋 ID は6文字。見間違えやすい文字（O, 0, I, 1 など）は使わない。
- URL は `https://<ユーザー>.github.io/puzzle-battle/#/room/ABC123`。「リンクをコピー」ボタンを付ける。対応している端末では共有ボタン（Web Share API）も出す。
- 定員は2人。3人目には「満員です」と表示する。部屋を作った人がホスト。
- 作ってから24時間たった部屋には入れない（データは小さいので自動削除はしない）。

### 9.2 データ構造（Realtime Database）
```
rooms/{roomId}/
  info: { createdAt, hostId, state: 'lobby'|'countdown'|'playing'|'roundEnd'|'finished', round, seed, startAt }
  players/{uid}: { name, game, ready, online, wins, lostRound }
  boards/{uid}: GameSnapshot   … 100ms に1回上書き
  attacks/{round}/{pushId}: { from, ap }
```

### 9.3 進み方
1. 両方の `ready` が true になったら、ホストが `seed` を決め、`state = 'countdown'`、`startAt = サーバー時刻 + 3000` を書く。
2. 両方とも `startAt` になったらゲームを始める。サーバー時刻とのずれは `.info/serverTimeOffset` で補正する。
3. 攻撃は `attacks/{round}` に push する。受け取る側は `from` が自分でないものだけを拾う。
4. 負けた側が `lostRound = round` を書く。勝った側の `wins` はホストが +1 する。どちらかが2勝したら `finished`。終わったあとは「もう一回」でロビーに戻る。

### 9.4 切断
- `.info/connected` と `onDisconnect` を使って `online` を管理する。
- 対戦中に相手が `online = false` になったら、ゲームを一時停止して「相手の接続を待っています…（残り秒数）」を出す。
- 15秒以内に戻れば続行。戻らなければ、残った側のラウンド勝ちにしてロビーに戻る。
- 同じブラウザでリンクを開き直すと、匿名認証の uid が同じなので同じプレイヤーとして戻れる。

### 9.5 セキュリティルール
- 読み書きできるのは認証済みのユーザーだけ。
- `players/{uid}` と `boards/{uid}` は本人だけが書ける。
- `info` はホストだけが書ける（作成時は誰でも書ける）。
- `attacks` は、部屋の players に入っている人だけが追加できる。

### 9.6 Firebase が未設定のとき
`firebaseConfig` が空なら、オンライン対戦メニューに「オンラインは準備中」と表示する。それ以外のモードは普通に動く。

| ゲーム | キーボード | タッチ |

| テトリス | ←→ 移動、↓ ソフトドロップ、Space ハードドロップ、↑/X 右回転、Z 左回転、C/Shift ホールド | 画面下のボタン（左・右・下・回転2つ・ホールド・ハードドロップ） |

- 効果音は WebAudio で作る簡単な音（音声ファイルは使わない）。音量は設定で変えられる。

## 12. テスト

- Vitest でテストする対象:
  - テトリス: 移動、SRS の壁蹴り、ライン消し、Tスピン判定、AP の表、おじゃまのせり上がり
  - ぷよ: 連結の判定、連鎖、得点、おじゃま数、おじゃまが巻き込まれて消えること
  - スイカ: 合体、得点、AP、石が砕ける判定、ゲームオーバー判定
  - 共通: 相殺、受け取り上限、シード付き乱数の再現性
  - AI: 置ける手を必ず返すこと。ふつう以上なら、明らかにラインが消せる場面で消すこと
  - 部屋ロジック: 偽の通信（メモリ上で動く Transport）を使って、ready → countdown → 攻撃 → 勝敗の流れを確認する
- 画面: ブラウザで実際に操作して確認する。
- プロジェクト用コマンド `/check` を作る: `npm run typecheck && npm test && npm run build`

## 13. 公開

1. GitHub に公開リポジトリ `puzzle-battle` を作る。
2. `.github/workflows/deploy.yml` で、main に push されたらビルドして GitHub Pages に公開する。
3. Firebase の設定値はコードに入れる（公開しても問題ない値。データを守るのはセキュリティルール）。
4. ユーザーにやってもらうこと: Firebase プロジェクトの作成（利用規約への同意）と、公開前の最終確認。
